# PageParcel 0.3.0

This release makes PageParcel simpler to use and smaller to trust. The record is the same, and the path to it is clearer.

## Highlights

- **A cleaner, light popup.** One **Save Page** button creates the full Trace Bundle. A short "Just one part" list covers Text only, Full page image, Visible area image, and Select image area.
- **File names you can read.** By default, every output is named `{date}_{title}_{type}`, for example `2026-11-01_Sallie Mae - Wikipedia_bundle.zip`, with no `PageParcel-` prefix.
- **Grouped Settings.** Appearance, Saving, PDF, and Keyboard shortcuts, with options shown only when they apply.
- **Checkable records, end to end.** Trace Bundle schema 1.1, a hash-sealed Page Text format, and `scripts/verify_bundle.py`, which checks saved ZIPs, folders, and Page Text files against their included hashes and can return `--json` for agents and scripts. Hashes show whether files changed; they are not a signature or proof of origin.
- **Agent-ready helpers.** `scripts/find_latest_bundle.py` finds the newest capture, and `docs/agents.md` shows how an agent can use PageParcel today.
- **Tighter security.** A stricter content security policy, wider redaction of sensitive fields in text, and a security audit that runs in CI.

## Removed: local OCR

I removed the in-browser OCR engine. It was the heaviest part of the extension and served one narrow feature. The unpacked extension drops from about 15 MB to about 0.5 MB, and the extension no longer needs `'wasm-unsafe-eval'`.

This is a real loss: **Text only** no longer reads text inside images, canvases, or scans. The screenshots in a Trace Bundle still show that text, so use **Save Page** or an image capture and a separate OCR or AI tool when it matters.

## Still true

Everything runs on your computer, and the extension does not upload page contents. Password fields are redacted from text; screenshots are not redacted.
